# V4 / 4.0.0：USD 与 USDT 独立放贷

V4 从当前 V3.5 策略扩展双币种，保留期限分层、精确期限定价、余额合并复投、托管归属和安全恢复规则。USD 与 USDT 可以同时运行，使用同一 API 客户端和账户写入门，各自拥有策略、资金上限、数据库、收益统计和恢复状态。

## 币种与金额

控制台、配置和日志统一显示 `USD` / `USDT`；交易所 USDT Funding 使用 `fUST`，钱包和账本使用 `UST`，价格检查使用 `tUSTUSD`。`USTF0` 不属于 USDT Funding，不会合并记账。所有本金、挂单、Credits、收益和资金上限均按原生币种记录，不把两币汇总成美元。

仅使用已有余额。默认关闭钱包转入；允许时仅将同一币种从指定钱包转入 Funding，不进行 USD 与 USDT 的兑换。每币的开关独立，设置前先暂停该币种。

USD 最低订单为 150 USD。USDT 使用最新正数 bid 计算 `max(150, 150 / bid)`，向上取整到 8 位小数；提交前再检查。汇率不能取得时 USDT 停写并进入恢复，USD 可以继续。报价每 30 秒刷新；失败立即失效。两个币共享每 60 秒最多 60 次新订单提交的持久预算。

## 配置和启动

已有 `default.cfg` 不需要被示例覆盖：USD 仍可从 `STRATEGY_V3` 读取策略，既有 USD 数据库继续使用。新安装参照 `default.cfg.example` 的 `STRATEGY_V4_USD`、`STRATEGY_V4_USDT` 两节。

USDT 默认禁用，没有默认最低净 APR 和绝对资金上限。总览和策略同时展示 USD、USDT：宽屏并排，窄屏上下排列。在 USDT 策略区设置短、中、长期三个最低净 APR 和正数 `max_lend_amount`，预览、保存草稿、应用，再在 USDT 总览中勾选启用。启用和同币种钱包转入设置立即保存，每币独立显示保存状态；失败保留选择并提供重试，保存尚未确认时阻止预检。LIVE 或恢复中需先暂停该币种再修改这两个设置。比例上限与绝对上限同时生效。APR 配置以百分数表示，例如 `5` 表示 5% 年化。

```powershell
python lendingbot.py --dashboard
# CLI：每个所选币种都要启用、通过只读预检，然后输入 LIVE
python lendingbot.py --live --currencies USD,USDT
```

控制台实盘预检针对按钮标注的币种；启动第二个币种时复用现有 V4 Worker。两币的编辑、草稿、预览和确认凭证独立，自动刷新保留未保存编辑。公共确认弹窗显示发起操作的币种，未读取的账户金额显示“—”。启动凭证绑定币种集合、配置、程序构建、ACTIVE 策略、账户与挂单集合，五分钟有效且只能使用一次；确认时重新读取账户检查。日志在同一页面提供全部、USD、USDT 筛选，未标记币种的系统日志在“全部”查看。

单币暂停不会停止另一个币种。全局停止终止 Worker 并暂停两币，不撤销交易所已有挂单。旧版 API 仍按 USD 处理，旧启动入口不会隐式启动 USDT。

## 状态和恢复

Schema 17 为数据库加上不可混用的币种命名空间。默认 USD 路径保持 `.state/lendingbot-v3.sqlite3`，USDT 为同目录的 `lendingbot-v4-usdt.sqlite3`；可在对应策略节配置 `statedbfile`，两条路径必须不同。单币数据库拒绝其他币种写入；历史相同交易 ID 不会跨库冲突。

升级已有库时先生成 `backups/schema-v16-时间.sqlite3`（版本可能更早），通过应用配置打开时同时生成同名 `.sqlite3.cfg` 配置副本。迁移保留 USD ACTIVE、DRAFT、PENDING、人工暂停、挂单归属和未决写入。新建 USDT 库保持暂停。历史 V3.5 分界继续保存，V4 另记录自己的升级分界与前后统计。

单币行情或账户对账错误只暂停该币种；账户级认证权限或数据库错误阻断两个币种写入。一个认证 WebSocket 订阅两个放贷市场，公共行情按市场分别订阅。恢复仍要求间隔至少 30 秒的两次完整权威 REST 对账，全局故障还需重新检查账户权限。人工暂停会撤销该币种自动恢复到 LIVE 的授权，但不会删除未知写入证据。存在需人工处理的未决写入时不得直接启动。

控制台守护只恢复本次明确授权的币种；配置、构建或控制权限改变时需要重新预检。已确认的策略安全切换后允许继续守护，但凭据、路径、启用和转入设置仍必须匹配。控制台重启后也需重新授权。

## 回滚

1. 全局停止 V4，确认 Worker 已退出并释放 LIVE 锁。
2. 保留当前两币数据库、配置和日志，再使用升级前的数据库备份与配套配置恢复 USD；不要把 Schema 17 库交给旧版本写入。
3. 切换到升级前代码，保持 PAUSED，读取真实账户核对挂单、Credits 和所有未决写入，再重新预检。

代码回滚不会撤销 USDT 账户挂单；旧 USD Worker 不会管理它们。USDT 状态库应保留以便重新使用 V4 对账和管理。

## 验证

`verify.ps1` 执行 Ruff、Python 编译、全部测试、核心覆盖率门槛、三个前端脚本语法检查、前端自动保存回归测试及 Git 空白检查。V4 测试使用模拟账户和临时 SQLite，覆盖双币下单、相同 ID 隔离、汇率门槛、共享额度、单币故障、全局恢复、人工暂停、启动凭证、策略凭证、HTTP 安全和兼容性。浏览器模拟服务为 `python tests/v4_dashboard_fixture.py`，仅使用假账户与临时配置，端口 8124，不连接真实交易所；可加 `--usd-live` 验证运行中币种的设置锁定与单币暂停。
