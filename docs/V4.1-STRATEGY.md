# V4.1 策略：LIMIT 与 FRR 系列比较

V3 旧策略与 V4.0 策略保留。新增引擎 `adaptive_net_yield_v2`、算法 `ADAPTIVE_NET_YIELD_V2`。
升级不自动替换 ACTIVE 或启动放贷。V4.1 通过独立运行验收后可预览、保存、应用，再人工预检启动。

## 类型与计息

| 界面类型 | 提交类型与参数 | 成交后的计息 |
|---|---|---|
| LIMIT | LIMIT，明确日利率 | 固定 |
| FRR | FRRDELTAVAR，偏移量0 | 随 FRR 浮动 |
| FRR Delta Fixed | FRRDELTAFIX，正或负偏移量 | 匹配前随 FRR 更新，匹配后固定 |
| FRR Delta Variable | FRRDELTAVAR，正偏移量 | 随 FRR 加偏移量浮动 |

Hidden 尚未进入此版本。各类型可独立勾选，必须至少选择一种。
浮动订单沿用可配置的 Variable 最高占比，包含已有贷款、已有挂单及拟议挂单；默认模板沿用现有10%上限。

## 收益比较与局限

沿用共同120天窗口、64条固定种子路径、保守第10百分位排序、长期优势检查、共享需求预算及撤挂冷却。
四种类型同价格的候选共享盘口容量，不重复占用需求。

FRR系列必须有至少20天真实FRR历史及未超过行情有效期的当前FRR。历史成交利率不能替代FRR。
当前 FRR 从公共 Funding ticker 的第0项读取，记录本地观察时间及来源。历史资金统计保持原时间戳，不能重标成新鲜报价。
预测使用历史两天FRR块，相对于当前FRR重定基准；Delta Fixed 在模拟成交时固定，Variable 在持有期间逐日计息。
自身成交等待表与持有样本按币种及类型隔离；样本稀疏时只使用保守市场先验，不借用其他类型的自身成交参数。
历史FRR不能精确还原待成交订单未来的排队位置；候选成交概率依然是当前报价的估计，不是成交保证。

当前报价仍须达到净年化底线，FRR系列还须通过持有期净年化第10百分位检查。
FRR系列挂单在成交前随FRR变化，可能在两次检查之间以低于报价门槛的利率成交；
**浮动贷款的未来利率也可能低于底线，此检查不构成收益保证，也不能强制提前收回贷款。**
预览显示各候选类型、预测收益、置信度及浮动利率风险说明。

## 资格与隔离

V4.1 模型、候选指针、评估报告和回放检查点与 V4.0 分开；模型版本参与策略与预检凭证绑定。
研究任务请求显式包含 currency 和 engine，恢复沿用原任务引擎。
研究不调用鉴权客户端或交易所写接口。

运行资格 `operationalReady` 与收益资格 `eligibleForLiveCandidate` 分开。运行验收不要求每种类型先有20条自身资金链；
缺少样本时使用现有市场先验，并逐类型显示低置信度。模型、行情、账户对账或未决写入不合格仍阻断启动。

严格收益研究仍要求60/15/15切分、收益及Bootstrap验收、训练集各类型至少20条自身资金链，
验证和测试窗口FRR有效覆盖至少95%。不足时收益状态保持“研究数据不足”，不会伪造收益优势。
回放同时比较各类型的独立方案与综合分配方案，公共成交只作为模拟容量。

运行报告位于 `.state/research/<currency>/operational-<modelId>.json`，绑定模型校验和及执行代码版本。
模拟验收使用临时数据库和内存交易所，验证四类型规划、持久化提交意图、拒绝、未知结果与重启读取。
报告修改、丢失或软件更新都会使预览/启动凭证失效，需要重新准备和预检。

正式启用仍需暂停对应币种、绑定通过运行验收的冻结模型、预览、保存、应用、预检及人工启动。
运行中不自动替换模型；新增真实成交和净利息用于后续候选模型和收益研究。

## 快速准备

`POST /api/research/v4/prepare` 接收 `currency`（USD/USDT）及 `engine=adaptive_net_yield_v2`。
任务异步执行，沿用 status/cancel/resume 接口；每币独立，准备失败不修改 ACTIVE。

优先复用本地数据；缺少FRR历史时读取最近30天公共资金统计，至少需要20个有效日。
再读取当前盘口、近期逐笔成交和当前FRR。鉴权读取继续由现有账户流程管理，准备与历史回补只用公共接口。
公共调用在两币间串行限速。取消、重启恢复会复用已入库的数据；完整90天公共历史继续后台回补。

历史训练一次流式扫描，用滚动窗口计算各订单创建时可知的条件，避免反复扫描同一行情或使用未来数据。
不足20个逐笔成交参考日时，用真实FRR历史作为滚动收益情景，模型标记 `dataBasis.rollingRateSource=FRR_HISTORY`。
这不增加逐笔覆盖、自己的成交样本或盈利资格，也不证明订单会成交。无法恢复的历史盘口缺口单独披露。

控制台每币分别展示运行验收、收益研究、各类型置信度和数据来源；选用候选模型只编辑该币种草稿。
资金上限、5%/10%净年化底线、120天期限上限、95%长期上限和现有Variable上限继续生效。

## 输入修复

空白或无效的最大放贷比例返回中文输入提示，不能隐式变成100%或暴露 decimal.ConversionSyntax。

## 实盘启动修复

双币 Worker 发布根级 USD 状态时同样转换 Decimal，包含版本对照里的挂单金额，避免首次输出状态就退出。
首次账户同步完成后更新实时决策时间，防止新读取的 FRR 被旧的循环时间误判为未来数据；显式回放时间仍保持固定。
贷款持有期的删失生存曲线按不可变样本缓存，沿用原有事件、风险集和严格概率边界，减少重复估算耗时，不改变收益规则。

## 实盘评估耗时修复

候选估值在单次决策内复用按兼容期限划分的成交价格分布：七天分位价、一天成交量和一小时趋势各自保留原有时间边界。
报价对应的兼容成交量通过累积金额查询，避免每一种订单类型重复排序、扫描同一批逐笔成交。
每个候选只选择一次持有期生存分布，64条固定种子路径仍使用原有抽样边界。
缓存仅属于本次决策，不在币种或决策时间之间共享；拟分配资金增加后的盘口竞争仍重新计算。

回归检查比较四种类型的完整候选收益路径、资金分配和保留/调整判断，验证优化前后结果一致。
软件版本绑定与启动预检保持生效；加载修复前重新验收原冻结模型，不自动训练、切换模型或修改风险参数。

## 重新启动后的暂停恢复

自适应模型、行情或决策日志问题造成的非自动恢复暂停，原先即使重新预检通过也只更新恢复目标，
未启动过的币种因此始终跳过首轮同步。用户重新预检并明确启动后，允许清除这三种已重新验证的旧暂停标记。
CLI 确认标记本身不能清除这些暂停；自动恢复中的账户问题、人工处理标记和其他安全原因继续保留原有屏障。
启动仍绑定币种、策略、模型、运行报告及账户摘要，首轮数据和决策日志检查继续在任何写入前执行。
