# Mika Lending Bot V3.2 无人值守自动自愈

V3.2 在 V3.1 策略不变的前提下增加只读自动修复。网络中断、截断响应、Bitfinex 408/425/429/5xx、行情过期、账户快照缺失或不守恒以及 SQLite 临时 busy/locked 会停止一切交易写入，并按 30 秒、60 秒、2 分钟、5 分钟退避；此后每 5 分钟继续安全读取。

恢复必须满足两次连续、至少间隔 30 秒的干净权威快照：钱包可用余额已知，Offers/Credits/Loans 完整去重，账户金额守恒，行情新鲜且没有未决写入。第二次确认只恢复原模式，不在同一周期下单；下一次正常策略周期才允许写入。

未知提交或撤单仍走严格的保护性 PAUSED 对账。机器人结合活动 Offers、请求时间附近的 Funding Trades 和历史 Offers 判断；唯一匹配或两次权威证据确认不存在后，还要再取得两次干净快照。多个可能匹配、数据库证据矛盾或无法证明唯一性时只能人工处理。

Dashboard 会显示故障类别、原模式和目标模式、`权威快照 1/2`、重试次数、下次探测时间、Worker 心跳和是否需要人工处理。这里没有可调总开关，避免误配置降低安全边界。

Dashboard 每次启动都会生成新的守护会话。只有本次会话中通过实盘预检并人工启动的 LIVE Worker 才能被自动拉起。Worker 五分钟没有心跳时，Dashboard 会先要求该具体进程安全退出，再终止仍卡死的同一进程并进行全新只读预检。Dashboard 重启、人工暂停/停止、配置、策略或构建变化会撤销旧授权。

以下情况永不自动恢复：人工暂停或停止、HTTP 401/403、API 权限错误、配置错误、版本不一致、数据库损坏或迁移失败、未知程序异常、多个候选交易写入。它们会明确显示“需要人工处理”。V3.2 不提供 Windows 开机自启，也不负责 Dashboard 自身崩溃后的系统级拉起。
