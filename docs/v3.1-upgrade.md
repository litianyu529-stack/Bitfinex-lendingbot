# Mika Lending Bot V3.1 精选升级

V3.1 在稳定 V3 的 50% / 35% / 15% 资金结构上加入期限评分、固定 150 USD 切片、六阶段累计重定价和更严格的账户安全校验。它不恢复旧增强版的无限跨池转移，也不会因为期限排名变化撤销仍有效的旧单。

## 防集中边界

- 可部署预算仅等于权威 Funding 钱包可用余额加机器人托管的未成交 Offers；Credits 不参与新挂单比例。
- 短、中、长期池最高分别为 60%、45%、25%，即基础比例最多上浮 10 个百分点。
- 有两个合格期限时，第一期限最多占该池 70%，其余分给第二期限。没有合格第二期限时该池不创建新订单；长期池只有 120 天一个配置候选时允许占长期池 100%。
- 排名变化只控制新增资金。已有订单即使暂时超过新上限也不会因此撤销，机器人会停止追加并等待自然成交或到期收敛。
- 行情不足、行情过期、钱包可用余额未知或账户组件不守恒时不写交易所。

## 期限确认

期限评分由成交需求 50% 和成交概率 50% 组成。新第一名必须连续 10 分钟比当前期限高至少 20% 才能生效；当前期限、挑战期限和计时均保存在 Schema 9，进程重启不会清零。

## 累计重定价

以下数字都是从订单最初创建时间开始计算的累计分钟，不是阶段之间的间隔：

- 短期：10 / 30 / 60 / 90 / 120 / 180
- 中期：20 / 60 / 120 / 180 / 240 / 360
- 长期：60 / 180 / 360 / 480 / 720 / 1440

前三阶段向市场可成交位置靠近，后三阶段从持久化市场锚点逐步靠近净 APR 底线。替换订单保留原期限、原始创建时间、当前阶段和市场锚点。

## 上线与回退

上线前必须创建配置、Schema 6 数据库、账户快照和 Git 引用备份。停止旧 Worker 后，以 PAUSED 模式完成 Schema 9 迁移、数据库完整性检查和权威账户预检，再人工恢复 LIVE。至少观察三个 60 秒周期，确认账户守恒、无 SAFE、无重复意图且旧单未因期限排名撤销。

若写入前失败，直接恢复 Schema 6 与原代码。若 V3.1 已产生交易所写入，先停止 Worker，按具体 Offer ID 对账并处理 V3.1 新单，再恢复稳定 V3；不得用旧数据库猜测接管。
